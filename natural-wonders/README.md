## 音效

100+ 条，全部由 `build_audio.py` 从时间轴锚点生成，改时间轴重跑即可。

- 开场 7 个光点：各一个 `point`
- 每个奇观：进入 whoosh + 场景句 chime + 描线 riser + 二次卡点 4 件套
  （hit / boom / sub / chime_hi）+ 12 个细节元素各一个 `point_hi`
- 珠峰铺垫：6 条事实各一个 tick + 长 drone
- 「地球之巅」：4 个字逐字递增（hit_soft / sub / tick），末字加 shatter
- DROP：boom + hit + shatter + shimmer + chime + sub，全片最响
- 音乐侧链闪避：7 dB，只在大卡点压，不超过 6~7 dB 避免"音乐变形"
- 音效总线 +3.5 dB，音乐 -8.5 dB

限幅器用 soft-knee：
`KNEE + (CEIL-KNEE) * tanh((mag-KNEE)/(CEIL-KNEE))`，KNEE=0.62 CEIL=0.97。
**不要**用 `LIMIT + (1-LIMIT)*tanh(...)`，那个写法会把峰值推到 1.0、动态全丢。

七个奇观的文案重点放在**反直觉的数字**上，而不是形容词：

- 瀑布：1.7 公里宽的水一起砸下，本地人叫「雷鸣之雾」
- 猛犸洞：名字跟猛犸象没关系，洞里从没挖出过一头

## 数据核实

所有数字来自 NPS 官方页面、UNESCO、英文维基原始条目。几处口径说明：

- 大峡谷**不是**世界最深峡谷（尼泊尔 Kali Gandaki 更深），所以文案说"最完整的 20 亿年岩层剖面"
- 维多利亚瀑布"世界最大水帘"是按宽度×高度综合算，不是按流量或落差
- 猛犸洞 686 km 是**已测绘**长度，每年还在增长
- 冰河湾潮水冰川取 NPS 现行口径的 7 条
- 贝加尔湖最大深度主流值 1,642 m（另有 1,637 m 说法）
- 珠峰 8,848.86 m 是含雪盖官方值，岩面 8,844.43 m

## 踩的坑

1. **heredoc 写长文件必被截断**。Bash 的 `cat > file << EOF` 在这个环境有长度上限，
   超过就静默截断（`wondering: here-document delimited by end-of-file`）。
   必须用 Write 工具，或拆成多个小文件再 `cat` 拼接。
2. **`drawWonder` 前必须 `translate(fx,fy)`**。漏了就会画到原点，
   表现为"右侧全黑、左侧有一团乱线"。我用右侧亮像素数验证抓到的。
3. **抽帧时间别落在切点上**。切点上有 45ms 闪白，抽到那帧整屏发白，
   会误判成"画面过曝"。要抽镜头中段。
4. **`mh preview --times` 必须 JSON 数组**：`--times '[1.5,4.5]'`。
5. **视觉模型的空间判断不可信**。它说冰河湾有个"深色长方形色块"，
   实际是冰墙的填充渐变；说"图形像拱门"其实判断对了。
   规则：视觉模型找方向（像不像、有没有重叠），数值验证确认（亮像素数、bbox 占比）。
6. **`ctx.filter = 'blur()'` 画发光层**，不要堆叠偏移副本——大字会变白块。
7. **循环里改 `globalAlpha` 必须 save/restore**，漏了后面所有文字被压暗。
8. **文字宽度必须和圆环半径一起算**。章节卡原来是 3 个字（七宗罪），
   换成 4 个字（自然奇观）后，文字半宽 210px 顶到了 R=206px 的圆环上，
   圆环直接从字的下半部穿过去。**换文案长度一定要重算排版几何**，
   验证方法：数"文字 bbox 内的圆环像素"，必须是 0。
9. **任何压在文字后面的水印/暗纹，只要肉眼可见就会被读成"脏污"**。
   大号 ghosted 数字（VII）从 alpha 0.085 降到 0.040 仍然被指为"阴影"，
   最后整个删掉才干净。宁可少一个装饰层。
10. **别用整帧平均差判断"画面活不活"**。线稿画在纯黑上，90% 像素是 0，
    整帧平均差被稀释到 2.4，看起来像静止；只统计有内容像素是 6.05，完全正常。
    测之前先问：这个指标的分母是不是包含了大量与内容无关的区域。

## 音效（2026-11-17 更新：换成 Freesound 实录素材）

15 个音效槽位全部从 numpy 合成换成 **Freesound CC0 实录素材**，
来源清单见 `assets/sfx-src/README.md`。

处理链：`prep_sfx.py`（解码 → 裁静音 → 截长度 → 归一 -3dBFS）。

**Freesound 下载的是预览版 MP3，前面有十几秒静音、电平极低（peak 0.17），
必须处理才能用。**

### 换成实录素材后必须重调混音

实录素材能量密度远高于合成音，同样的 dB 值会响很多：

- 音乐 -8.5 → -9.5 dB，音效总线 +3.5 → +1.5 dB
- 「地球之巅」段从音乐的 1.56 倍压到 0.88x
- `point_hi`（72 次）从 -20 → -26 dB（新素材余韵 480ms，旧的只有 240ms）
- `shimmer` / `chime` 全线 -4~5 dB

### 音效总线必须单独限幅

新素材叠加后**音效总线自身 peak 到 1.584**，主限幅器要硬压 1.376 → 0.87。
修法：给音效总线加独立 soft-knee 限幅（knee 0.55 / ceil 0.86），压完 0.854。

### 选素材的硬标准

1. **attack < 100ms** 才能当卡点音。下载量最高的 Cinematic Impact 起音 1.67 秒，
   而 132 BPM 一拍只有 454ms，直接淘汰。
2. **实测 attack / tail / 频谱重心**，不能只看下载量和评分。
3. 持续型素材（开头就满电平）不能当冲击用，会糊成一片。
4. 渐强型素材（GLEAM-GLOW）要手动截掉前 0.35s。

## 强化版（2026-11-17 20:20）— 转场冲击 / 开场提速 / 加特效 / 音色变脆

老大反馈四条：转场音效没劲、开头优化、加特效、音效要清脆震撼且更大声、配音闷。

### 诊断（全部量出来的）

| 问题 | 客观证据 |
|------|---------|
| 「闷」 | 混音里 20-120Hz 占 **48.3%**，3kHz 以上只有 **3.2%** |
| 「转场没劲」 | 每个转场只比前 200ms 响 **1.01~1.19 倍**，而 drop 是 11 倍 |

闷的根因：音效把低频灌满了（音乐本体低频只占 28.8%）。
转场没劲的根因：转场正好落在音乐最响的位置，hit 只有 0.1s，被 200ms 均值摊平。

### 解决手段

**1. 给 `add()` 加三个滤波/塑形参数**
- `hp` 高通 — 治闷最有效的一招，不让小音效往 20-150Hz 灌能量
- `shelf` 高频搁架 — 「脆」的控制杆
- `punch` 瞬态塑形 — 包络压缩，把身体压下、保住前几毫秒

按用途分档：
- 清脆类（point/tick）：hp 700-1500, shelf 6-8, punch 0.3
- 震撼类（impact/boom）：hp 35-90, punch 0.45-0.9，**高通不能太高否则没重量**
- 氛围类（drone/riser）：不动低频

**2. 转场三层叠**：crack（亮瞬态）+ body（低频 thump）+ tail（短 boom）

**3. 转场单独深闪避**：18dB / attack 45ms / release 220ms，给冲击挖洞。drop 20dB。

**4. 总线处理**：限幅 KNEE 0.62 → 0.78（主限幅器原来压了 97750 个采样，等于削平每个瞬态）；
加 1.7:1 温和压缩 + makeup gain 提响度。

**5. 关键素材推到满刻度**：hit/boom/shatter/sub 的 peak 只有 0.71（-3dBFS），
这是转场顶不上去的真正瓶颈。重新归一到 0.99。

### 画面特效（新增三个函数）

| 函数 | 作用 |
|------|------|
| `burstRings()` | 同心冲击环 + 30 条长短不一的放射线 |
| `sliceTear()` | 横向切片错位，7 条带，位移量跟 glitch 包络 |
| `chromaSplit()` | 红青重影，只在最硬的切点（gl>0.30） |

glitch 包络从 0.85/130ms 提到 1.00/100ms。
验证撕裂生效：逐行找最佳匹配位移，**25 行里 15 行位移 >2px，最大 36px**。

### ⚠️ 两个测量陷阱（血泪）

**1. 测量窗口选错会得出完全相反的结论。**
我先用 `peak(d-0.30, d-0.02)` 测 drop 前的 bed，得出「drop 只有 +3.1dB，比转场还弱」，
然后去猛加 drop 增益——全是白费。正确测法是「事件后 100ms vs 事件前 1 秒」：
drop 其实是 +10.5dB，层级一直是对的。
**测冲击力要测「事件本身 vs 它之前的环境」，不是「事件前后各 200ms」。**

**2. 闪避曲线的最小值必须落在事件点上。**
原 `duck()` 用高斯曲线，最小值在窗口 30% 处。配合 45ms attack，
最深的地方落在 hit 之后 120ms，冲击完全没吃到闪避的好处。
改成「attack 斜坡 → 45ms 保持 → release 斜坡」的折线形状才有效。

### AAC 编码会吃掉响度
mix.wav 的 peak 0.79 / RMS 0.165，编码成 mp4 后变成 peak 0.94 / RMS 0.157。
**print 时留 -2.4dBFS 余量**，否则编码器削峰反而让整体变小。
